## 2026-11-03 — RuleChain L1-7w CODI: one latent does the work, then the chain sits at a fixed point (z_1..z_5 centered cosine 0.97-0.997); latents 3-6 add ~nothing (codi, run_id: 20261104-022824_codi_v2-l1to7w-depth2-codi-latent-ablation)

**Goal:** Are CODI's 6 latents all used on RuleChain, or only the first few? The latent-count sweep (truncation) suggested accuracy saturates at ~3 latents, but truncation shortens the sequence (out of distribution). Here all 6 positions run and single latents or tails are replaced, plus cosine geometry of the latents.
**Mechanism / model:** `codi`, checkpoint-17820 of 20261103-193425 (levels 1-7, 4-7 up-weighted, 6 latents), CPU fp32.
**Data:** canonical L1-L7 RuleChain test, 3,500 items; ablation means from valid.json (2,000) so no test statistics enter; resample donor = seeded random permutation of test items.
**Command:** `scripts/ablate_latents_rulechain_codi.py` (`eval_command.txt`). Sites: z_s = the projected vector fed INTO latent pass s+1; z_0 = prj(hidden at <bot>). Accuracy is the teacher-forced answer token at the ':' of "<eot> The answer is:" (clean 0.744 = generated 0.743 on GPU / 0.744 on CPU).
**Headline results:** (overall; L4 / L5 / L7)
- clean 0.744; 0.858 / 0.660 / 0.270
- single site, mean: z_0 0.744, z_1 0.741, z_2 0.735, z_3 0.735, z_4 0.728, z_5 0.744. Resample: z_0 0.743, z_1..z_5 0.701-0.711 (and L1 drops to ~0.94: a foreign latent's content gets read).
- mean-ablate the tail z_t, t >= s: s=1 0.322 (0.118 / 0.042 / 0.040), s=2 0.687 (0.778 / 0.498 / 0.204), s=3 0.733, s=4 0.742, s=5 0.744. All six: 0.315.
- Truncation sweep (generated, `eval_synthetic_codi.py --inf_latent_iterations k`, not separately logged; in manifest `truncation_sweep_generated`): k=0 0.391, 1 0.391, 2 0.711, 3 0.737, 4 0.741, 5 0.744, 6 0.744.
- Geometry: cross-item cosine at the same site 0.95 for z_0, 0.63 for z_1..z_5; item-specific energy share 5% for z_0, 37% for z_1..z_5. Between sites, centered cosine z_1..z_5 vs each other 0.97-0.997; z_0 vs the rest ~0.61.
**Interpretation:** z_0 carries nothing (mean or resample costs 0). The first latent pass writes the item's content into z_1, and passes 2-5 then reproduce almost the same vector (centered cosine >= 0.97): the recurrence reaches a fixed point after one or two passes. That is why ablating any single one of z_1..z_5 barely matters (the others hold a copy) while ablating all of them costs everything (0.744 -> 0.322, the same as 0 latents). z_2 adds a little (tail >= 2: -0.06, mostly L5-L7), z_3 onward nothing measurable. So the model uses 6 latents as about one or two passes of extra computation plus redundant copies, not as serial steps; more latents would not be expected to buy more rules under this recipe. Matches SIM-CoT's account of latent homogeneity without step-level supervision.
**Gotchas hit:** The 64-item smoke test showed cross-item cosine 0.99 because its first 64 items are all L1; the full set gives 0.63. Raw cosine is dominated by a shared vector (norm ~33), so use the centered numbers. Diagonals of the KxK cosine matrices print 0.997-0.998 instead of 1.0: a few items' vectors evidently are not unit after normalisation (not investigated; off-diagonal values are unaffected beyond that ~0.3%). Added map_location to eval_codi.build_model's torch.load and a CPU hardware label in eval_synthetic_codi.py so CODI checkpoints evaluate on the Mac.
**Caveats:** One checkpoint, one seed. Ablation shows what this model uses, not what latents could do. Truncation of k <= 1 is out of distribution and so is mean_tail_ge_1 to a lesser degree. No matched CODI-0 yet, so whether the one used latent beats a trained 0-latent model is still open.
