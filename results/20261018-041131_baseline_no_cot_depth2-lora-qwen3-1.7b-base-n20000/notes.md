## 2026-10-18 — Qwen3-1.7B-Base LoRA n=20000 on depth2 no-CoT: L1 1.00, L2 0.88, L3 0.21 (baseline_no_cot, run_id: 20261018-041131_baseline_no_cot_depth2-lora-qwen3-1.7b-base-n20000)

**Goal:** Does a small answer-only fine-tune unlock 2+ rule no-CoT chaining that prompting could not (layer scan: every pretrained model at floor from 2 rules; prompt check: 24 shots / explicit instruction give at most 0.13 at 2 rules)? A few hundred examples fixing it would mean the ceiling was task specification; needing thousands would mean a skill the weights have to learn. One point of a 0/200/1k/5k/20k curve.
**Mechanism / model:** `baseline_no_cot` (fine-tuned no-CoT), Qwen/Qwen3-1.7B-Base, 28 layers, frozen; LoRA r=16 on all linears, 20000 answer-only training examples (levels 1-4), 2 epochs = 1250 steps, 1060 s. compute_steps=0. Architecture diagram: claude.ai artifact "Depth2 LoRA Setup".
**Data:** train = nested prefix of one level-interleaved shuffle of depth2 train, levels 1-4 (0 test questions overlap with train). Test = first 200 items per level, levels 1-4 (n=800); seed=0.
**Hyperparams:** {'train_n': 20000, 'train_levels': [1, 2, 3, 4], 'train_subset': 'nested prefix of one level-interleaved shuffle', 'data_seed': 0, 'lr': 0.0002, 'batch_size': 32, 'epochs': 2, 'min_passes': 10000, 'min_epochs': 2, 'lora_rank': 16, 'lora_alpha': 32, 'lora_targets': 'all-linear', 'schedule': 'cosine, 3% warmup', 'per_level': 200, 'decoding': 'greedy, 6 tokens', 'prompt': "zero-shot 'Question: ...\\nAnswer:'"}
**Command:** `bash scripts/pod/lora_depth2.sh run` -> `scripts/lora_depth2.py` (one process, all sizes, fresh adapter per size) on RunPod A40 (secure).
**Headline results:** per level 1 -> 1.00, 2 -> 0.88, 3 -> 0.21, 4 -> 0.07; unparseable 0.000.
**Interpretation:** Whole curve: n=0: L1 0.15 / L2 0.01; 200: 0.90 / 0.12; 1k: 0.99 / 0.36; 5k: 1.00 / 0.57 (L3 0.10); 20k: 1.00 / 0.88 (L3 0.21, L4 0.07). 200 examples teach the format (L1 0.15 -> 0.90, above the best prompt's 0.87) but leave L2 at the prompting ceiling (0.12 vs 0.13); L2 then climbs steadily with data (0.36, 0.57, 0.88) and L3 starts to move only at 5k-20k. So the one-rule ceiling of the pretrained models is not a prompt / task-specification artifact: composing a second rule in one pass is a skill that takes thousands of examples to learn, and each extra rule takes more. A 1.7B pretrained model learns L2 from far less data than GPT-2 small (0.88 from 20k x 2 epochs on levels 1-4, vs GPT-2's 0.77 from 100k x 25 epochs on levels 1-12, `20261014-021704_filler_tokens_v2-depth2-nocot-25ep`), but GPT-2 is better at L3/L4 (0.49 / 0.27 vs 0.21 / 0.07), plausibly because it trained far longer.
**Gotchas hit:** The image's python is PEP 668-managed: install into a `--system-site-packages` venv. Training throughput about 37 examples/s on the A40 (bf16, batch 32).
**Caveats:** One seed, one LR, rank 16, no hyperparameter search; small sizes get many epochs (200 x 50) so passes are not equal across sizes (min 10k, 20k gets 40k). Train on levels 1-4 only, so L3/L4 numbers are in-distribution but under-trained relative to GPT-2. 200 test items per level (95% CI about +-7 pt at 0.5). Adapters not saved.
