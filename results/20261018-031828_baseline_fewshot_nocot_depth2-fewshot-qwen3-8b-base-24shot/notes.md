## 2026-10-18 — Qwen3-8B-Base 24shot no-CoT on depth2 L1-4: L1 0.80, L2 0.13 (baseline_fewshot_nocot, run_id: 20261018-031828_baseline_fewshot_nocot_depth2-fewshot-qwen3-8b-base-24shot)

**Goal:** Prompt check for the depth2 layer scan: is the one-rule no-CoT ceiling of pretrained models (every model, 24-64 layers, at floor from 2 rules) an artifact of an unclear 6-shot prompt? Conditions: base models with 24 shots instead of 6; instruct models with an explicit instruction, 0 and 6 shots.
**Mechanism / model:** `baseline_fewshot_nocot`, Qwen/Qwen3-8B-Base (released weights, not fine-tuned), 36 layers, compute_steps=0. Condition: 24-shot completion prompt (base model).
**Data:** synthetic-depth2 test, levels 1-4, first 100 items per level (n=400); run seed=0.
**Hyperparams:** {'n_shots': 24, 'shot_seed': 0, 'shot_source': 'train, same level', 'per_level': 100, 'levels': [1, 2, 3, 4], 'cot_per_level': 0, 'max_new': 6, 'cot_max_new': 200, 'reach_floor': 0.08, 'loops': None, 'cot_loops': None, 'decoding': 'greedy', 'backend': 'vllm', 'chat': False, 'instruction': None, 'thinking': None, 'force_number': False}
**Command:** `bash scripts/pod/depth_prompt_check.sh run` -> `scripts/depth_scaling_fewshot.py` (see eval args in hyperparams) on RunPod A40 (secure).
**Headline results:** no-CoT per level 1 -> 0.80, 2 -> 0.13, 3 -> 0.04, 4 -> 0.03; bare-number rate 1.00. L2 answers: 0.07 = the rule-1 intermediate, 0.07 = rule 2 applied to the start. Reference: 6-shot base run (L1 0.84, L2 0.06).
**Interpretation:** Across the 6 conditions the 2-rule accuracy stays at or near floor (0.02-0.05; best 0.13 for Qwen3-8B-Base at 24 shots, 95% CI about 0.08-0.21, n=100) while 1-rule accuracy is 0.69-0.87. More shots and an explicit instruction move L1 a little and L2 not at all (the Qwen3 0-shot run is a forcing artifact, see headline). Unconstrained, the instruct models ignore 'answer only the number' from 2 rules on and start writing the steps (smoke test), i.e. they read the task correctly and reach for CoT. Together with the CoT references in the scan (Qwen3-8B-Base 0.66 at L2), this argues against 'the prompt is ambiguous': the models understand the task, do one rule per forward pass, and cannot compose a second one silently without training.
**Gotchas hit:** Qwen3's no-think chat template makes the reply open with a newline, so a newline stop gave empty outputs: chat mode has no newline stop and parses the first non-empty line. argparse reads `--slug-suffix -24shot` as a flag: use `--slug-suffix=-24shot`. Unconstrained instruct replies are CoT, hence `--force-number`.
**Caveats:** 100 items per level (95% CI about +-9 pt at 0.5, about 0.01-0.10 at 0.04). One instruction wording, one shot seed. Digit-constrained decoding forbids any tokens before the answer, which can hurt a model whose preferred first token is text (clearly so for Qwen3 0-shot). 7-8B models only; the scan's 32B is not re-tested here. Pod had no .git: `git.commit` unknown; code = `scripts/depth_scaling_fewshot.py` + `scripts/pod/depth_prompt_check.sh` as committed with these runs.
**Next:** The open test is the tiny fine-tune (LoRA on Qwen3-1.7B with ~200 vs ~5k depth2 no-CoT examples): if a few hundred examples unlock 2 rules, the gap was task specification; if it needs tens of thousands (as GPT-2 did), it is a skill the weights lack.
